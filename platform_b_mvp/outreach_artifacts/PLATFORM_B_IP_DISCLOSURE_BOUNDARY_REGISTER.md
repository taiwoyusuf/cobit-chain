## Purpose

This register defines what may be shared during early Platform B academic, funding, university, technology transfer, and non-confidential industry discussions.

It protects Platform B by separating:

1. information that may be shared non-confidentially
2. information that should only be shared after an appropriate protection process
3. information that should not be shared externally

## Core rule

Start every external discussion as non-confidential unless a formal protection process is already in place.

Do not disclose proprietary implementation logic during first-stage outreach.

## Green zone: safe for non-confidential first discussion

The following may be shared in a first discussion:

- Platform B name
- high-level problem statement
- non-confidential reviewer brief
- IP-safe funding outreach packet
- public one-line description
- high-level v0.2 demo boundary
- high-level v2 backlog candidate names
- high-level research themes
- non-confidential meeting agenda
- non-confidential collaboration ask
- public doctrine statements
- public Git evidence tag names
- high-level screenshots if they do not reveal proprietary logic
- public repository link if already intentionally public

## Yellow zone: share only with caution

The following should be shared only after confirming the audience, purpose, and protection process:

- detailed architecture narrative
- detailed evidence flow explanation
- detailed assurance lifecycle mapping
- implementation screenshots showing internal logic
- prototype workflow walkthroughs
- detailed scoring factor categories
- detailed research methodology
- detailed funding strategy
- detailed commercialization pathway
- university-specific proposal drafts
- invention disclosure drafts
- unpublished manuscript drafts
- detailed regulatory mapping
- detailed product roadmap

## Red zone: do not share without protection

Do not disclose the following in a first discussion:

- scoring logic
- internal registry schemas
- reliance packet structure
- right-to-rely scoring model
- protocol assurance matrix
- action surface assurance schema
- retrieval risk gate logic
- governance theater detection logic
- proprietary evidence mappings
- proprietary implementation strategy
- confidential commercialization strategy
- confidential partner strategy
- source code not already intended for public review
- non-public employer information
- regulated operational examples from work
- patient, customer, GMP, validation, or confidential operational data
- private grant strategy
- private visa or immigration strategy
- private financial information

## First-meeting opening script

I can explain Platform B at a non-confidential level.

I am not ready to disclose proprietary scoring logic, schemas, reliance packet design, or implementation details until the right IP protection process is clear.

My goal today is to confirm research fit, funding fit, and the correct protection pathway.

## First-meeting closing script

Before I share deeper technical details, I would like to understand the appropriate university or partner process for protecting intellectual property.

Would the next step be an invention disclosure discussion, NDA process, grant concept note, faculty collaboration review, or technology transfer intake?
