# Exception-Only Alert Model Schema

## Platform

Platform B v0.6 - Operational Trust Passport and Ambient Evidence Mesh

## Purpose

The Exception-Only Alert Model defines when Platform B should stay quiet, raise a yellow review condition, raise a red stop condition, or generate an evidence packet for review.

The model is designed to reduce noise.

Platform B should remain quiet when evidence is trusted and only alert when operational trust is at risk.

## Core doctrine

Quiet when trusted. Alert when trust is at risk. Evidence when action is challenged.

## Continuity from v0.5

The device senses. Platform B assures.

A regulated action is not trusted because one signal is green. It is trusted when the evidence mesh agrees.

## Alert states

| Alert state | Meaning |
|---|---|
| quiet | Evidence is complete, current, coherent, and no review condition exists |
| informational | Evidence exists for traceability but no action is required |
| yellow | Review is required because evidence is incomplete, stale, pending, or needs confirmation |
| red | Action is not admissible because evidence is missing, failed, conflicting, expired, or blocked |
| escalated | Exception requires higher-level review or closure decision |
| closed | Exception has been reviewed and closed under the demo rule set |

## Alert trigger categories

| Trigger category | Example trigger |
|---|---|
| evidence_gap | Required evidence is missing |
| stale_evidence | Evidence is outside its valid time window |
| conflicting_evidence | Two or more evidence signals disagree |
| reviewer_pending | Reviewer decision is required but not complete |
| red_witness_signal | A context witness generated a red signal |
| expired_window | Dose, cleaning, calibration, review, shipment, or action window expired |
| object_not_ready | Person, room, equipment, procedure, environment, or time state is not ready |
| mesh_disagreement | Ambient Evidence Mesh cannot produce coherent trust state |
| passport_not_assured | Operational Trust Passport is not assured |
| ledger_stop | Action Admissibility Ledger records stop decision |

## Required alert fields

| Field | Description |
|---|---|
| alert_id | Unique exception-only alert identifier |
| alert_state | quiet, informational, yellow, red, escalated, or closed |
| alert_category | evidence_gap, stale_evidence, conflicting_evidence, reviewer_pending, red_witness_signal, expired_window, object_not_ready, mesh_disagreement, passport_not_assured, or ledger_stop |
| alert_title | Human-readable alert title |
| alert_summary | Human-readable alert explanation |
| workflow_context | Workflow or operational context |
| action_context | Specific action being evaluated |
| affected_object_refs | Person, room, equipment, procedure, environment, time, action, or site readiness objects affected |
| evidence_mesh_id | Ambient Evidence Mesh linked to the alert |
| passport_refs | Operational Trust Passports linked to the alert |
| witness_chain_refs | Context Witness Chains linked to the alert |
| ledger_refs | Action Admissibility Ledger entries linked to the alert |
| reviewer_packet_refs | Reviewer Evidence Packets generated by the alert |
| required_action | none, monitor, review, stop, escalate, or close |
| action_admissibility | proceed, review_required, stop, expired, or not_applicable |
| trust_state | assured, partially_assured, not_assured, pending, expired, or retired |
| generated_at | Alert generation timestamp |
| generated_by | System, user, or demo process that generated the alert |
| assigned_reviewer_id | Reviewer assigned to yellow, red, or escalated alert |
| reviewer_decision | approved_to_proceed, rejected, escalated, closed, pending, or not_required |
| closure_reason | Reason alert was closed, when applicable |
| guardrail_status | Demonstrator-only, non-production, no validated-use claim |

## Alert rule table

| Condition | Alert state | Required action |
|---|---|---|
| Evidence complete, current, coherent, and admissible | quiet | none |
| Evidence captured for awareness only | informational | monitor |
| Evidence exists but reviewer confirmation is needed | yellow | review |
| Required evidence missing | red | stop |
| Evidence expired | red | stop |
| Evidence conflicts | red | stop or escalate |
| Reviewer decision pending | yellow | review |
| Reviewer rejects action | red | stop |
| Red exception unresolved | escalated | escalate |
| Exception reviewed and resolved | closed | close |

## Relationship to v0.6 objects

The Context Witness Chain records the event sequence.

The Ambient Evidence Mesh connects the evidence relationships.

The Operational Trust Passport summarizes the resulting trust state.

The Action Admissibility Ledger records why the action was allowed, blocked, expired, or routed for review.

The Reviewer Evidence Packet gives the reviewer a structured evidence bundle.

The Exception-Only Alert Model decides whether Platform B stays quiet, routes review, stops action, escalates, or closes the condition.

## Guardrails

This schema is for a controlled non-production demonstrator.

It does not support patient use, batch release, shipment release, clinical use, regulatory submission use, validated GMP use, autonomous execution, or production compliance.

It does not replace QMS, MES, LIMS, EMS, Lasair, validated systems, or human review.
