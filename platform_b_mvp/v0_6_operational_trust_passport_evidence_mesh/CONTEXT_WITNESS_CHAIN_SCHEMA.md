# Context Witness Chain Schema

## Platform

Platform B v0.6 - Operational Trust Passport and Ambient Evidence Mesh

## Purpose

The Context Witness Chain records the ordered sequence of context witness events that support an operational trust state.

A witness event does not approve work.

A witness event contributes evidence to the Ambient Evidence Mesh, Operational Trust Passport, and Action Admissibility Ledger.

## Core doctrine

The device senses. Platform B assures.

A regulated action is not trusted because one signal is green. It is trusted when the evidence mesh agrees.

## Protected phrase

Quiet when trusted. Alert when trust is at risk. Evidence when action is challenged.

## Witness source types

| Source type | Meaning |
|---|---|
| qr | QR scan or QR-linked object witness |
| nfc | NFC tag or tap event |
| ble | BLE beacon proximity or location signal |
| wearable | Glasses, badge, watch, phone, or wearable capture |
| phone | Phone-based scan, photo, video, or manual observation |
| iot_node | M5Stack, ESP32, Raspberry Pi, or low-cost IoT node |
| sensor | Temperature, humidity, pressure, door, motion, vibration, or other sensor |
| particle_counter | Particle counter export or observation event |
| ems | Environmental monitoring system signal or exported record |
| manual | Manual entry, reviewer attestation, or operator declaration |
| upload | Uploaded file, screenshot, export, log, or evidence packet |
| system | System-generated context witness event |

## Chain event types

| Event type | Meaning |
|---|---|
| asset_scan | Asset, equipment, room, tag, or procedure was scanned |
| presence_observed | Person, device, or object presence was observed |
| evidence_capture | Evidence was captured or uploaded |
| environment_snapshot | Environmental context was captured |
| time_window_check | Validity window was checked |
| procedure_step_check | Procedure step or version was checked |
| equipment_status_check | Equipment status was checked |
| reviewer_attestation | Reviewer made or recorded an attestation |
| exception_raised | Yellow, red, expired, or escalated exception was raised |
| exception_closed | Exception was closed or resolved |
| passport_generated | Operational Trust Passport was generated or updated |
| ledger_written | Action Admissibility Ledger entry was written |

## Required chain fields

| Field | Description |
|---|---|
| witness_chain_id | Unique context witness chain identifier |
| chain_context | Workflow or operational context |
| action_context | Specific action being evaluated |
| chain_sequence | Ordered witness events supporting the trust state |
| event_id | Unique witness event identifier |
| event_order | Order of the event in the chain |
| source_type | QR, NFC, BLE, wearable, phone, IoT, sensor, particle counter, EMS, manual, upload, or system |
| source_label | Human-readable source description |
| event_type | Witness event type |
| observed_object_id | Person, room, equipment, procedure, environment, time window, or action observed |
| observed_object_type | Object type being witnessed |
| actor_id | Operator, reviewer, system, or demo actor associated with the event |
| event_timestamp | Event timestamp |
| evidence_reference | Evidence record, file, screenshot, export, or packet reference |
| prior_event_id | Previous witness event in the chain, when applicable |
| next_event_id | Next witness event in the chain, when applicable |
| trust_signal | green, yellow, red, pending, expired, or informational |
| action_admissibility | proceed, review_required, stop, expired, or not_applicable |
| evidence_mesh_id | Ambient Evidence Mesh linked to the chain |
| passport_refs | Operational Trust Passports generated or updated by the chain |
| ledger_refs | Action Admissibility Ledger entries generated by the chain |
| integrity_state | complete, incomplete, stale, conflicting, or unverifiable |
| guardrail_status | Demonstrator-only, non-production, no validated-use claim |

## Chain integrity rules

| Rule | Result |
|---|---|
| Events are ordered, timestamped, and linked | complete |
| Required event is missing | incomplete |
| Event timestamp is outside the valid window | stale or expired |
| Event contradicts another witness or record | conflicting |
| Source cannot be traced | unverifiable |
| Red signal appears in chain | stop |
| Yellow signal appears in chain | review_required |

## Relationship to v0.6 objects

The Context Witness Chain records the event sequence.

The Ambient Evidence Mesh connects the evidence relationships.

The Operational Trust Passport summarizes the resulting trust state.

The Action Admissibility Ledger records why the action was allowed, blocked, expired, or routed for review.

## Guardrails

This schema is for a controlled non-production demonstrator.

It does not support patient use, batch release, shipment release, clinical use, regulatory submission use, validated GMP use, autonomous execution, or production compliance.

It does not replace QMS, MES, LIMS, EMS, Lasair, validated systems, or human review.
