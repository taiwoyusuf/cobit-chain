# Live Site Readiness Evaluation Loop

## Platform

Platform B v0.7 - Assurance-Sensed Site Runtime

## Purpose

The Live Site Readiness Evaluation Loop defines how Platform B v0.7 repeatedly evaluates whether a site, room, workflow, equipment group, or action context is ready before action proceeds.

The loop receives normalized witness events, updates evidence relationships, refreshes passports, evaluates admissibility, suppresses noise when trusted, and routes human review when trust is at risk.

## Core doctrine

The future regulated site will not only be monitored. It will be assurance-sensed.

## Carry-forward doctrines

The device senses. Platform B assures.

A regulated action is not trusted because one signal is green. It is trusted when the evidence mesh agrees.

The environment is part of the evidence.

Quiet when trusted. Alert when trust is at risk. Evidence when action is challenged.

## Loop question

Can this action proceed now, based on the current evidence state of the person, place, equipment, procedure, environment, time, reviewer state, and exception state?

## Evaluation loop stages

| Stage | Purpose |
|---|---|
| receive_runtime_event | Receive a normalized witness event from the Runtime Context Witness Event Bus |
| bind_context | Bind the event to person, room, equipment, procedure, environment, time, action, and site context |
| check_required_evidence | Determine whether required evidence exists for the action context |
| update_evidence_mesh | Update supporting, contradicting, expired, missing, or reviewer-required relationships |
| refresh_passports | Refresh operational trust passports affected by the new event or evidence state |
| evaluate_readiness_dimensions | Evaluate people, room, equipment, procedure, environment, time, evidence, review, and exception readiness |
| calculate_runtime_state | Produce trusted, review_required, stopped, expired, pending, or retired runtime state |
| write_admissibility | Record proceed, review_required, stop, expired, or not_applicable decision |
| alert_or_stay_quiet | Stay quiet when trusted or raise yellow, red, expired, escalated, or closed exception state |
| route_human_review | Generate reviewer route and packet when human decision is required |
| record_runtime_trace | Record runtime evidence lineage and challenge-ready trace |

## Readiness dimensions

| Dimension | Runtime readiness question |
|---|---|
| people_readiness | Is the actor known, authorized, trained, present, and linked to the action context? |
| room_readiness | Is the room, hood, cleanroom, suite, or area acceptable for the action context? |
| equipment_readiness | Is the equipment identified, status-known, evidence-linked, and not blocking action? |
| procedure_readiness | Is the correct procedure, checklist, instruction, or step in scope? |
| environment_readiness | Are EMS, Lasair, particle, cleaning, certification, or environmental signals current and coherent? |
| time_readiness | Are dose, cleaning, calibration, review, shipment, or action windows still valid? |
| evidence_readiness | Is required evidence present, current, coherent, and traceable? |
| review_readiness | Is reviewer decision not required, completed, pending, rejected, or escalated? |
| exception_readiness | Are there unresolved yellow, red, expired, escalated, or blocking exceptions? |

## Runtime decision rules

| Condition | Runtime state | Runtime decision | Alert behavior |
|---|---|---|---|
| All required readiness dimensions are assured | trusted | proceed | quiet |
| Required evidence exists but reviewer confirmation is needed | review_required | review_required | yellow |
| Required evidence is missing | stopped | stop | red |
| Evidence or time window expired | expired | expired | red |
| Evidence conflicts across sources | stopped | stop or review_required | red or yellow |
| Evidence is still being gathered | pending | review_required | informational or yellow |
| Event is informational only | trusted | not_applicable | quiet |
| Reviewer approves continuation under demo rule set | trusted | proceed | quiet |
| Reviewer rejects continuation | stopped | stop | red |

## Relationship to v0.7 runtime

The Device-Agnostic Witness Adapter normalizes source signals.

The Runtime Context Witness Event Bus routes normalized events.

The Live Site Readiness Evaluation Loop evaluates the current site and action context.

The Assurance-Sensed Site Runtime records the resulting operational trust state.

## Guardrails

This schema is for a controlled non-production demonstrator.

It does not support patient use, batch release, shipment release, clinical use, regulatory submission use, validated GMP use, autonomous execution, or production compliance.

It does not replace QMS, MES, LIMS, EMS, Lasair, validated systems, or human review.
