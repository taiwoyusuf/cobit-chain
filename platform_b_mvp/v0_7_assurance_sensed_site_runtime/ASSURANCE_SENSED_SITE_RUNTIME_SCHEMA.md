# Assurance-Sensed Site Runtime Schema

## Platform

Platform B v0.7 - Assurance-Sensed Site Runtime

## Purpose

The Assurance-Sensed Site Runtime defines how a regulated site can continuously receive device-agnostic witness events and convert them into runtime assurance signals before action proceeds.

v0.7 moves Platform B from static operational trust artifacts into a live runtime model where people, rooms, equipment, procedures, environmental signals, time windows, evidence, review status, and exceptions are evaluated as a connected operational trust state.

## Core doctrine

The future regulated site will not only be monitored. It will be assurance-sensed.

## Carry-forward doctrines

The device senses. Platform B assures.

A regulated action is not trusted because one signal is green. It is trusted when the evidence mesh agrees.

The environment is part of the evidence.

Quiet when trusted. Alert when trust is at risk. Evidence when action is challenged.

## Runtime objective

The runtime should answer one operational question:

Can this action proceed now, based on the current evidence state of the person, place, equipment, procedure, environment, time, reviewer state, and exception state?

## Runtime layers

| Layer | Purpose |
|---|---|
| witness_ingestion_layer | Receives QR, NFC, BLE, wearable, IoT, EMS, Lasair, manual, upload, and system events |
| context_normalization_layer | Converts source-specific inputs into a common runtime event shape |
| evidence_binding_layer | Links events to evidence records, objects, workflows, and action context |
| evidence_mesh_update_layer | Updates evidence relationships as new events arrive |
| passport_refresh_layer | Refreshes operational trust passports when evidence changes |
| readiness_evaluation_layer | Evaluates site, room, equipment, procedure, environment, time, and action readiness |
| admissibility_layer | Decides whether action is proceed, review_required, stop, expired, or not_applicable |
| exception_alert_layer | Stays quiet when trusted and alerts only when trust is at risk |
| reviewer_routing_layer | Routes evidence packets to reviewers when human decision is required |
| audit_trace_layer | Records runtime decisions and evidence lineage for challenge review |

## Runtime object types

| Object | Purpose |
|---|---|
| runtime_site_state | Current assurance-sensed state of a site, area, room, or workflow |
| runtime_event | A normalized signal received by the runtime |
| runtime_context | Person, room, equipment, procedure, environment, time, and action context |
| runtime_evidence_link | Evidence relationship created or updated by the runtime |
| runtime_passport_state | Current trust passport state after refresh |
| runtime_admissibility_state | Current action admissibility state |
| runtime_exception_state | Current yellow, red, expired, escalated, or closed condition |
| runtime_review_route | Reviewer routing record when human review is required |
| runtime_trace | Runtime trace of event, decision, evidence, and review path |

## Runtime state rules

| Condition | Runtime state | Runtime decision |
|---|---|---|
| Evidence mesh agrees and no blocking condition exists | trusted | proceed |
| Evidence exists but reviewer confirmation is required | review_required | review_required |
| Required evidence is missing | stopped | stop |
| Evidence is stale or time window expired | expired | expired |
| Evidence conflicts across sources | stopped | stop or review_required |
| Runtime event is informational only | trusted | not_applicable |
| Yellow exception is active | review_required | review_required |
| Red exception is active | stopped | stop |
| Reviewer approves continuation under demo rule set | trusted | proceed |
| Reviewer rejects continuation | stopped | stop |

## Relationship to v0.6

v0.6 defines the evidence artifacts.

v0.7 defines the runtime that updates, refreshes, evaluates, routes, and records those artifacts as site context changes.

## Guardrails

This schema is for a controlled non-production demonstrator.

It does not support patient use, batch release, shipment release, clinical use, regulatory submission use, validated GMP use, autonomous execution, or production compliance.

It does not replace QMS, MES, LIMS, EMS, Lasair, validated systems, or human review.
