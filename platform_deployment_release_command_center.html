The release discipline that keeps the platform stable.

This page defines how COBIT-Chain moves safely from local development to Azure deployment. It covers backup, compile check, route verification, Git commit, Azure redeploy, smoke testing, password variables, rollback, and release evidence.
Deployment principle: Every platform release should be testable, reversible, and traceable. No route should be pushed without local compile, local smoke test, route verification, Git status review, clear commit message, Azure deployment check, and production URL validation.

Release Control Gates

These gates define the minimum discipline for moving from local development into Azure production.

Release governance
Gate 01

Backup Gate

Before modifying app.py, create a timestamped backup so the route injection can be reversed quickly.

  • app.py backup
  • HTML file backup
  • Marker-safe injection
  • Rollback path
Gate 02

Compile Gate

Run Python compile check before local testing, Git commit, or Azure deployment.

  • py_compile
  • No syntax errors
  • Route function valid
  • Startup block intact
Gate 03

Route Gate

Verify route markers, HTML file references, and local URLs before pushing.

  • Select-String marker
  • Installed URLs
  • Local smoke test
  • Password gate test
Gate 04

Git Gate

Use a clean commit that includes only the required files for the feature being released.

  • git status
  • git add selected files
  • clear commit message
  • git push origin main
Gate 05

Azure Gate

After deployment, validate the production route, password gate, and related navigation links.

  • Azure URL
  • Route opens
  • Password works
  • No broken display text

COBIT-Chain Deployment and Release Command Center defines the release-control discipline for Platform A/B. It does not replace enterprise DevOps, cybersecurity review, validation, QA approval, or production change control. Its purpose is to make local builds, Git commits, Azure deployments, route smoke tests, rollback, and release evidence repeatable.
