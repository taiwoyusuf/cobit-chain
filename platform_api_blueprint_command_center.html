The service boundary that turns dashboards into a real platform.

The API Blueprint defines how COBIT-Chain moves from premium command-center pages into service-backed architecture: trust scoring endpoints, evidence retrieval, CI and equipment lookup, Governance Vision responses, MCP tool access, audit logging, and identity-aware control boundaries.
API principle: Every API must return evidence-backed operational truth, not marketing language. The platform should expose controlled services for trust state, evidence lineage, CI passports, equipment readiness, AI-agent tool use, and wearable point-of-work decision support.

Five API Domains

These domains define the service layer that turns static pages into a callable platform. They can start as Flask routes and later move into Azure Functions or API Management.

Service blueprint
Domain 01

Trust State API

Returns trust score, confidence level, trust decay state, readiness interpretation, and recommended action.

  • /api/trust-score
  • /api/trust-state
  • /api/trust-decay
  • /api/decision-confidence
Domain 02

Evidence API

Retrieves evidence lineage, sufficiency, freshness, source records, attachments, and audit replay packages.

  • /api/evidence
  • /api/evidence-lineage
  • /api/evidence-pack
  • /api/replay
Domain 03

CI & Equipment API

Looks up CI, equipment, passport, owner, support group, lifecycle state, access state, and operational readiness.

  • /api/ci-passport
  • /api/equipment-passport
  • /api/owner-map
  • /api/readiness
Domain 04

MCP Tool API

Provides controlled AI tool contracts for evidence retrieval, trust queries, action checks, and decision support.

  • /api/mcp/tools
  • /api/mcp/query-trust
  • /api/mcp/get-evidence
  • /api/mcp/action-guard
Domain 05

Governance Vision API

Returns short, point-of-work trust summaries for smart glasses, QR scans, voice queries, and mobile views.

  • /api/vision/lookup
  • /api/vision/summary
  • /api/vision/action
  • /api/vision/hud

API Request-to-Trust Flow

The platform must never produce trust claims without evidence. Every request should pass through identity, evidence retrieval, trust logic, response shaping, and audit logging.

Evidence before claim
Service Flow
1. RequestUser, wearable, dashboard, or MCP tool asks for trust state, evidence, passport, or action guidance.
→
2. Identity CheckVerify caller, role, session, source, and allowed operation before returning sensitive evidence.
→
3. Evidence RetrievalPull relevant records, source links, freshness state, ownership, lifecycle, and dependency data.
4. Trust ComputationApply trust rules, decay, confidence weighting, missing evidence penalties, and claim limitations.
5. Response + ReplayReturn concise decision support and log the query, evidence references, score basis, and limitations.

COBIT-Chain Platform API Blueprint is an engineering planning layer for the future service boundary. It does not activate production APIs, replace QA, bypass validation, or authorize automated changes. It defines how the platform should expose evidence-backed trust services as Platform A matures into Platform B.
