## AIMS ↔ VSA architectural seam

The current architecture distinguishes an AI Management System (AIMS) from Validation Standing Assurance (VSA).

An AIMS is treated as the organizational AI-management control plane for matters such as:

- AI inventory / estate discovery;
- Context of Use;
- ownership and accountability;
- risk-management controls;
- supplier/model oversight;
- validation/evaluation evidence;
- lifecycle change;
- monitoring;
- incident/CAPA interfaces;
- QMS integration;
- continual improvement.

VSA remains the narrower present-state assurance question for a specific regulated AI use:

`AI System × Version × Context of Use × Deployment / Operating Environment`

Core invariant:

`AIMS_IN_CONTROL != SPECIFIC_AI_USE_CURRENTLY_SUPPORTABLE`

Additional preserved distinctions include:

- `AI_INVENTORY_EXISTS != AI_ESTATE_COMPLETE`
- `CONTEXT_OF_USE_DOCUMENTED != CONTEXT_OF_USE_CURRENT`
- `SUPPLIER_APPROVED != EXACT_MODEL_VERSION_CONTEXT_SUPPORTABLE`
- `TRIGGER_DETECTED != STANDING_LOST`
- `NO_TRIGGER != STANDING_CURRENT`
- `MODEL_PERFORMANCE_ACCEPTABLE != CURRENT_RELIANCE_SUPPORTABLE`
- `EVIDENCE_CURRENT != INFERENCE_SUPPORTED != VALIDATION_STANDING_SUPPORTABLE`
- `ISSUE_CORRECTED != STANDING_REESTABLISHED`
- `CAPA_CLOSED != AI_RELIANCE_REESTABLISHED`
- `VALIDATION_STANDING_SUPPORTABLE != HUMAN_AUTHORITY_VALID`
- `VALIDATION_STANDING_SUPPORTABLE != ACTION_ADMISSIBLE`

Historical validation remains part of chronology even when current standing changes or requires reassessment.
